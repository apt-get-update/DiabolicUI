= Testing

Plain Lua 5.1 against a fake 3.3.5 client, no game needed.

[source,bash]
----
lua5.1 tests/test_chat_cleaner.lua                         # one file
lua5.1 tests/test_chat_cleaner.lua TestChatCleaner.test_x  # one test
tests/run_all.sh                                           # all of them, six at once: not while the game runs
JOBS=1 tests/run_all.sh                                    # one after another, about 5 minutes
luacheck .                                                 # unused locals, undefined globals (.luacheckrc)
stylua .                                                   # formats the Lua (stylua.toml)
tests/coverage/run.sh                                      # line coverage, before a release
----

The coverage report leaves out what the compiler adds and nothing can run (the `return` after a
tail call, a jump after a `break`): `tests/coverage/report.lua` lists them.

Close the game first for the slow ones (`+test_session_*.lua+`, the full run): they use a lot of
memory. Otherwise run only the files you touched.

== When one fails

It prints the test, the line, and what it expected:

----
tests/test_session_windows.lua:834: expected: 12, actual: 14
----

* *You changed that value on purpose:* update the number in the test.
* *You didn't:* your edit broke something. The test's comments say what it checks.
* *An `ERROR:` with a file and line:* the code crashed, and would in game too.

== Writing a session test

[source,lua]
----
local client = Client.boot({ world = {...}, savedVariables = {...} })
client:FireEvent("PLAYER_TARGET_CHANGED")
client:Tick(1)
-- check frames, texts, settings
Session.assertClean(client)  -- fails on any Lua error or blocked action
----

When the fake client (`+tests/mocks/client*.lua+`) lacks something, add it the way 3.3.5's FrameXML
has it. More in `tests/README.md`.

== What tests can't tell you

If it looks right, if Blizzard's real frames behave like the fake ones, and timing. The QML isn't
loaded at all. All of that needs the game, or the editor.
