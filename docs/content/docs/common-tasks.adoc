= Common Tasks

The changes asked for most, step by step.

== Change a size, a gap or a place

Paddings, gaps, sizes, positions, fonts and colours are values in
`settings/`, one file per area: `blizzard.lua` (the windows), `unitframes.lua`,
`actionbars.lua`, `chat.lua`, `tooltips.lua`... Change the value, `/reload`.
What every window shares is in `windows/components/` instead: see below.

To find the right value:

. In game, `/fstack` and hover the thing: it shows the frame's name
  (`MailFrame`, `BrowseNextPageButton`...).
. Search the code for that name (`modules/`): next to it, the code reads
  `config.something` or `spec.something`.
. Search `settings/` for `something`. A comment beside it says what it does.

In `settings/blizzard.lua`, each window has its own table (`mail`, `auction`,
`spellbook`...) for what's only its own. For example:

|===
| To change | Value

| The gap between the Escape menu's buttons | `gamemenu.button_spacing`
| Where the durability figure sits | `durability.position`
|===

A `position` reads `{ point, frame, its point, x, y }`; `UICenter` is our frame
in the middle of the screen. Higher `x` goes right, higher `y` goes up.

After a window change, open it and run `/dui layout`: it lists in the chat
what's now off (overlaps, text outside its panel, buttons out of line).

*Moving a frame just for you, in game:* `/dui move` (the minimap, the chat,
the menu buttons, the quest tracker, TrinketMenu). To add one there, copy the
TrinketMenu line in `GetMovers` (`modules/menu/movers.lua`).

== Change what every window shares

The generic window and its controls are in `windows/components/`: `Window`,
`Button`, `ScrollBar`, `DropDown`, `EditBox`, `CheckBox`, `Tab`, `Banner`,
`CloseButton`, `Section`, `Columns`, `Panel`, `ListRow`, `Bar`, `Pager`, `TabRow`.
Change one and every window inherits it.

*With the editor:* *Components* in its top bar, or *Styled as...* on a part
(after a `/dui layout all` with this version). Save, then `/reload`. The size of a
scroll bar's arrows, a close button and a checkbox show in the open window at
once; the rest shows after `/dui layout`.

*By hand:* change the property, one a line, then `lua5.1 tools/positions.lua`,
which writes `settings/components.lua`: don't change that one. What only one
window needs stays in its table in `settings/blizzard.lua` (a `panels` line, its
`button` size...).

== Restyle a Blizzard window

Most Blizzard windows are restyled from one line each in the `panels` table of
`settings/blizzard.lua`. The bank's:

[source,lua]
----
{ frame = "BankFrame", band = false, insets = { 24, 40, -6, -34 }, offset_y = -4,
  title = "BankFrameTitleText", close = "BankCloseButton" },
----

|===
| Key | Means

| `frame` | The window's name (`/fstack` shows it)
| `addon` | The addon it comes with, if it loads later (`Blizzard_TrainerUI`)
| `insets` | How far our window reaches past it: left, top, right, bottom
| `offset_y` | Moves it down (negative) to line up with the other windows
| `title` or `text` | Its title: its own text's name, or a Blizzard string (`"TRADE"`)
| `close` | Its close button's name
| `band` | `false`: no red band under the title
| `background` | The painted picture behind it: `slabs`, `lava`, `zoltun`, `artisan`...
| `tabs` | Its tabs' names without the number (`"MacroFrameTab"`)
| `footer` | The highest button of its foot (`"MacroExitButton"`)
|===

More keys are explained in the comment above the table. To restyle a new
window, copy the line of one that looks like it, change the names, then
`/reload`, open it, and `/dui layout` to see what's off. Windows that need more
than a line have their own file in `modules/blizzard/` (code).

== Fix a visual bug

A button in the wrong place, in any window. Every named part of the windows
is in `windows/<its window>.qml`, a part being a QML block with its anchors:

[source,qml]
----
Part {
    id: whoFrameEditBox
    name: "WhoFrameEditBox"
    kind: "EditBox"
    pin: "all"
    anchors.bottom: whoFrame.bottom
    anchors.bottomMargin: 103
    anchors.horizontalCenter: whoFrame.horizontalCenter
    anchors.horizontalCenterOffset: -20
    width: 296
    height: 32
}
----

*With the editor:* `tools/editor.py` (needs PySide6, Pillow and `lua5.1`;
`tools/install-editor.sh` puts it in your desktop's menu). Each
window opens as it is in its file, with our art under its boxes; a window with
tabs has them on top, each showing only its own parts.

* Press a part to pick it (again: the one under it; right-click lists all that's
  there, Tab goes through them). Drag it: it snaps to the others' edges (Alt: it
  doesn't), what's placed on it follows.
* The gold handles size it, on any side (the other side stays).
* The dots are its 9 points, the yellow one the point it's placed by. Drag a dot
  onto another part's point to place it there: it stays where it is.
* Arrows move it 1 (Shift 10), Ctrl + arrows size it. Ctrl+Z, Ctrl+Shift+Z,
  wheel to zoom, the middle button or the empty space to pan, F to fit.
* *Save* (Ctrl+S) writes the files, then `/reload`.
* *Show* hides the frames, texts, art or outlines. The art is ours and the game's
  (read from its MPQ archives the first time, kept in `tools/art/game/`).
* *Rules* lists what breaks the windows' rules in the tab shown (`tools/rules.js`,
  the numbers in `settings/blizzard.lua` `layout`), as you drag. Click one to
  pick its part.

*By hand:* change a part's block, then `lua5.1 tools/positions.lua`. Each part
needs one anchor across and one down, on one frame of its file, with plain
numbers (the tool says what it can't read). A `pin` puts it in
`settings/positions.lua` (`"all"`, or only its `"place"` or `"size"`), which the
game loads and the tool writes: don't change that one. Without a pin a part
follows the scan. Say why with `//` lines over its block: they're kept.
A `Ghost` stands for a frame with parts on it that isn't in that window's file.

*Filling the files:* `/dui layout all` opens every window that needs no NPC
and each of its tabs (open the others yourself while it's on: mail, auction
house, bank, vendor, trainer...), `/reload`. The editor reads it by itself, or
run `lua5.1 tools/positions.lua`: pinned parts stay, the others follow the scan.
It also writes `tools/layout.json` for the editor (not in git).
`/dui layout left` (said too when it starts and when `all` ends, shown in the
editor) lists what's left: the windows we style not scanned, or scanned by an older
version, the tabs not visited, and any window seen shown that we don't style.
Our own parts are named after their window (`ClassTrainerFrameDiabolicBand`).

== Put a part in a window's red band

In its `panels` line: `band = { left = { "ItsSearchBox" }, right = { "ItsButton" } }`.
The band lines them up and gives them its fonts.

== Style another addon

. `/fstack` on its window: the frame's name (`GroupBulletinBoardFrame`...).
. Add a `panels` line in `settings/blizzard.lua` with its addon's folder name:
  `{ frame = "ItsFrame", addon = "ItsAddon", panel = false, insets = { 24, 40, 24, 36 } }`.
  It's styled as soon as that addon loads. `panel = false` when the addon
  places its window itself (most do).
. `/reload`, open it, `/dui layout`, then adjust `insets` (left, top, right,
  bottom: how far our window reaches past its frame).

Parts it adds only once shown go under `late` (Auctionator's line is the
example). When the table isn't enough, it gets its own file like
`modules/blizzard/bulletinboard.lua`: that's code.
